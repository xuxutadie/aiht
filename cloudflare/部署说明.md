# 作品创作台：Cloudflare 正式在线版

本版使用 **Workers + D1 图片分片 + Queues + 私有 SQLite Durable Objects（DO）**，无需开通 R2。网页复用上级 `public/`，电脑关闭后由 Cloudflare 提供在线服务。

## 服务分工与当前范围

- Workers 提供网页、登录后的 API、同源校验和权限检查。
- D1 保存账户、会话、创作计划、任务、作品说明、算力账本、加密配置及图片分片。
- Queues 执行生图任务。每个任务只能领取一次，重复消息不重新发起收费绘图；结果不确定时保留预留，由管理员核对。
- 私有 SQLite DO 执行较重的密码派生及图片分片读取。密码任务串行处理，图片以流转发；DO 不持久保存密码和图片，正式资料仍保存在 D1，内部计算接口不向公网开放。

新用户首次注册赠送 **10 点算力**；每张成功作品消耗 **1 点**，明确失败不扣，结果未知等待核对。算力用完提示“请联系管理员进行补充算力”。当前没有充值或支付功能。

当前保留所有成功作品，**每位用户只保留最近 4 张的上限尚未启用**。首次云端部署建立全新账户库，不自动迁移本机账号、密码记录、API 配置或图片；需要迁移时另行确认数据范围并备份。

## 取景与手动提示词

第4步支持主体展示范围（自动/全身/半身/特写）和场景景别（自动/远景/中景/近景）。第5步预览可直接改写、保存、恢复当前答案的模板。原引导和确认要求保留，修改后须重新自查；最终Job冻结已经确认的提示词，队列沿用该快照，不受后续草稿修改影响。

数据沿用`plans.answers` JSON，新增可选键`subject_framing`、`scene_distance`、`custom_prompt`，不改表结构。省略`custom_prompt`使用模板；存在但空白允许存草稿，不能确认/生成；合法手改最长4000字。preview保留原响应并增加`template_prompt`、`prompt_mode`，自动模板过长但手改合法时另给`template_error`并保留手写内容。恢复失败不会删除手写稿。原草稿没有新增字段时保持兼容。

## 图片容量与费用边界

图片按原始字节分片，每片最多 768 KiB，Base64 编码后最多 1 MiB，适应 D1 单行大小限制；下载时由私有 DO 逐片读取和解码，公共 HTTP 入口转发流。

整个图片库共享 **320 MiB 编码容量预算**，计算已分配图片的编码大小及进行中任务的存储预留。新任务先原子预留算力和最坏图片容量；容量不足返回 `storage_capacity`，不创建任务、不发送队列、不调用收费模型。预算满后保留已有作品，拒绝新的生成，不自动删除旧图。未知任务或未完成分片占用的容量，在核对后按任务状态处理。

这是应用级图片编码预算，不是 Cloudflare 账户总容量或账单上限。账户、计划、账本和索引也占用 D1 空间。D1、Workers、Queues 和 DO 分别受套餐配额约束；免费配额耗尽可能拒绝操作，付费套餐按其规则计费，不能承诺永远零费用。Seedream 实际出图仍按服务商规则收费；自动验证只用模拟响应，不做真实付费调用。

## 首屏构建与加载恢复

云端部署复用已随锁定Wrangler安装的esbuild，不新增依赖。`npm run build`将`public/app.js`及其模块打包、压缩CSS并内嵌到生成首页，输出至`.wrangler/frontend-assets/`；原公开模块保留以兼容旧缓存。脚本只复制明确列出的网页文件，不复制账户数据、环境文件或密钥。

`.wrangler/frontend-policy.js`自动记录脚本和样式的精确SHA-256，Worker将它们加入CSP，仍不允许`unsafe-inline`或`unsafe-eval`。必须同时构建并发布Worker和静态资源，不能手工修改生成HTML、单独替换首页或单独修改哈希。`npm test`通过pretest先构建；Wrangler的dev、check和发布也会执行自定义构建。

初始化、登录后的初始化及进入工作台的草稿读取GET有15秒超时，包含响应正文读取。网络挂起时显示错误与重连入口；用户点击后才重试，重复点击不会同时创建多个启动请求。创建草稿、保存、登录和绘图POST没有新增自动重试。该处理减少资源请求并避免启动永久挂起，不能保证跨境网络速度。

2026-11-15此次只更新版本及静态资源，使用`wrangler versions upload --keep-vars`上传、再用`wrangler versions deploy <实际版本ID>@100 --yes`发布，沿用既有域名和触发器，不调用`triggers deploy`。需要改变域名、路由或定时触发器时，须另外核对对应权限和配置。

## 安装与检查

Wrangler **4.162.0** 已获准作为本项目的开发工具安装，版本由锁文件固定。本项目测试使用 Node.js 24 内置 SQLite，请使用 **Node.js 24 或更高版本**。以下命令均在 `cloudflare/` 目录执行：

```text
npm ci
npm test
npm run check
```

`npm run check` 对应 `wrangler deploy --dry-run`，只检查构建与绑定，不发布网站。无需另装生产运行库；安装、测试和检查不会调用语言模型或真实绘图接口。

## 登录与最少 OAuth 权限

下列为最初 `workers.dev` 部署时使用的最少 OAuth 权限，不包含自定义域名管理权限，也不需要 R2、Pages、Workers KV 或 AI 服务权限。当前 `xqd-ai.cn` 已通过控制台绑定；后续 Wrangler 发布若提示域名管理权限不足，应核对具体缺失权限，不能通过删除 `routes` 配置规避。

```text
npx wrangler login --scopes account:read user:read workers_scripts:write d1:write queues:write
```

- `account:read`、`user:read`：确认当前账号与账户归属。
- `workers_scripts:write`：管理本项目 Worker、Secret、触发器及 DO 类迁移。本机4.162.0虽然也接受旧的workers:write，但实际发布接口需要这项脚本权限。
- `d1:write`：创建与初始化本项目 D1。
- `queues:write`：创建和绑定生成队列。

浏览器授权时核对账号和权限清单。OAuth 权限面向账户资源；命令只应操作为本项目新建的资源。可用名称可通过 `npx wrangler login --scopes-list` 查看。

## 新建云端资源

当前配置的 Worker 为 `ht`，已绑定自定义域名 `https://xqd-ai.cn/`，并保留 `https://ht.ai-ht.workers.dev/` 入口；D1 为 `aiht-creation-db`，Queue 为 `aiht-generation`。Worker原名为`aiht-creation-studio`，改名使用既有项目的名称设置完成，不以新建项目替代。先核对资源名称与用途，不要覆盖、删除或初始化用途不明的既有资源。

`wrangler.jsonc` 的 `routes` 明确声明 `{ "pattern": "xqd-ai.cn", "custom_domain": true }`，后续发布应保留该配置和 `workers_dev: true`。这只是给原 Worker 增加访问入口，不新建或迁移数据库、图片存储、队列。域名激活、HTTPS 证书及国内网络直连仍需单独验证；新域名首次使用需要重新登录，原账户、算力和作品继续共用原数据库。生产环境未设置 `PUBLIC_URL`，继续使用各入口自身的同源校验。

```text
npx wrangler d1 create aiht-creation-db
npx wrangler queues create aiht-generation
```

把创建结果中的真实 `database_id` 填入 `wrangler.jsonc`，替换全零占位值。确认 `DB` 指向本项目的新库后建立表：

```text
npx wrangler d1 execute DB --remote --file=./schema.sql
```

配置已声明私有 `RUNTIME_SERVICES` 绑定，以及 `v1` 的 `new_sqlite_classes: ["AihtRuntimeServices"]` 迁移。首次部署随 Worker 创建 SQLite DO 类与命名空间，不需手工建立 DO 数据库。更新时保留既有迁移记录，不通过删除命名空间或改写首个迁移处理故障。

## 初始密钥与发布

生产环境需要两个 Workers Secret：

- `CONFIG_ENCRYPTION_KEY`：密码学随机生成的 32 字节主密钥，以 Base64 编码，保护老师在后台保存的绘图 API 密钥。长期妥善保管；更换后原配置将无法解密。
- `ADMIN_SETUP_TOKEN`：供负责人首次启用网站时输入的强随机初始化口令，至少 16 个字符，建议由 32 字节随机值生成，防止其他访问者抢先建立管理员。

通过交互输入或标准输入传递 Secret，不写入命令参数、Git、前端、日志或公开文档。

首次创建 Worker 与 DO：

```text
npm run deploy
```

未设置初始化口令时，公开初始化接口返回 503，访问者无法建立管理员。随后设置两个 Secret，再次发布并检查：

```text
npx wrangler secret put CONFIG_ENCRYPTION_KEY
npx wrangler secret put ADMIN_SETUP_TOKEN
npm run deploy
```

访问命令输出的 HTTPS 地址，由负责人输入初始化口令并自行设置管理员密码，再到后台配置自己的 Seedream API。绘图密钥以 AES-GCM 加密后保存 D1，学生端仅获得脱敏提示。

## 验证与运行限制

Node 测试使用内置 SQLite 适配 D1，覆盖分片写入与流读取、容量预占、HTTP 权限、加密、算力账本、队列幂等和私有 DO。单独执行真实本地 workerd 集成验收：

```text
node tests/workerd.integration.mjs
```

脚本使用 Wrangler 已安装的 Miniflare 与 esbuild 开发依赖，在临时环境验证 20 MiB 图片、27 个分片、每片最多 1 MiB、读回 SHA 一致，以及成功扣 1 点和预留归零。测试入口不包含在生产 Worker，真实付费 API 调用为 0。

本地交互预览可在被忽略的 `.dev.vars` 中配置独立测试初始化口令和主密钥，再执行：

```text
npx wrangler d1 execute DB --local --file=./schema.sql
npm run dev
```

普通 Workers Free HTTP 每请求的 CPU 预算当前为 **10 ms**；SQLite DO 默认每请求 **30 秒 CPU**，免费套餐支持 SQLite 型 DO。密码派生放在私有 DO 串行执行，图片分片解码也在 DO 内完成。网络等待、端到端耗时和 CPU 用时分别计算；本地运行通过不能当作线上套餐配额已经验收。

当前已通过79项Node测试、106项Python测试、dry-run、真实本地workerd分片与OpenAI-HK模拟单图验收，以及经DO的本地登录。正式网站沿用既有D1、队列、DO与Secret；增加服务商不需要执行建库脚本或迁移表结构。真实付费出图由负责人配置API后自行发起，自动验收不消耗绘图余额。正式发布后持续检查：

- 初始化口令、Secure Cookie、同源请求与不同账户的数据隔离。
- D1、Queues、DO 绑定与迁移；私有图片查看、下载及大图流读取。
- 成功扣 1 点、失败释放、未知冻结、人工核对及容量不足时不调用模型。
- 电脑与手机的注册、七步创作和算力耗尽提醒。
- 控制台 Worker/DO CPU、D1 读写和存储、队列用量。

自动验收不发起真实付费绘图。检验 Seedream 效果时，应由负责人明确发起对应的收费调用。

## 更新与回退

更新前保留数据备份和部署版本，先执行 `npm test`、`npm run check`，再执行 `npm run deploy`。代码回退不会回退 D1 数据；不要删除 D1、图片分片、DO 命名空间或账本处理异常。已有结构升级需要迁移与备份方案，首次建库脚本不能替代升级迁移。

可用官方 registry 检查开发依赖：`npm audit --registry=https://registry.npmjs.org`。镜像 registry 不提供 audit 时，不能将“不支持审计”当成“无漏洞”。

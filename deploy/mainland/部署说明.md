# 作品创作台：腾讯云／Linux 服务器部署（新手版）

本说明部署仓库当前 `main` 分支的正式 Python + SQLite 版本。适用于腾讯云等采用 systemd 的 Linux 服务器，不需要安装 pip 包、Node.js、构建工具或单独的数据库服务。

只想在 Windows 本机试用的用户，请返回仓库首页，双击 `启动作品创作台.cmd`。要让学生通过公网访问，才需要部署服务器。

**请选择正确路线：**第一次安装按第 1～6 步操作；已经运行 Python 版的用户按第 7 步升级；曾使用旧 Cloudflare 版、需要搬旧数据的用户才阅读[旧数据迁移说明](../../docs/migration/旧Cloudflare数据迁移.md)。新站空库安装无需迁移。

## 1. 准备环境

你需要一台支持 systemd 的 Linux 服务器、SSH 登录权限（能执行 sudo 或以 root 登录）、Python 3.11 或更新版本；正式上线还需要自己的域名、Nginx 和有效 HTTPS 证书。中国大陆公网网站请先按接入商要求办理备案等手续，未就绪时只做私有测试。

通过腾讯云控制台或 SSH 连接服务器，检查：

```bash
python3 --version
command -v python3
systemctl --version
nginx -v
```

Python 低于 3.11 时，先通过对应 Linux 发行版的官方软件源安装合适版本。现有宝塔等面板若已安装 Nginx，请沿用现有 Nginx，不要重复安装或覆盖其它站点；没有 Nginx 时再安装。

| 位置 | 用途 |
|---|---|
| `/opt/aiht-creation-studio` | 应用源码，由 root 管理，应用只读 |
| `/var/lib/aiht-creation-studio` | SQLite、账户、API 配置、私有作品图片，权限由 systemd 管理 |
| `127.0.0.1:8321` | Python 后端内部地址，不对公网开放 |
| `aiht` | systemd 动态运行身份，无需手动创建登录用户或授予 sudo |

以下均使用这些目录。如果端口占用、目录有其他用途，或者需要改目录，请先核对并同步修改临时和正式服务、Nginx。不要直接覆盖其它服务。

## 2. 获取最新源码（仅全新安装）

在服务器终端执行，下载 `main` 分支。无 Git 时，也可从 GitHub 仓库首页选择 `Code → Download ZIP`，上传解压到服务器一个新的目录（不要使用旧版本的目录）。

```bash
git clone --branch main --single-branch https://github.com/xuxutadie/aiht.git aiht-source
```

下载成功后进入新源码目录，构建发布包（ZIP 用户将下面的 `aiht-source` 换成自己的解压目录）：

```bash
cd aiht-source
release_dir=$(mktemp -d)
release_file="$release_dir/aiht-release.tar.gz"
python3 scripts/build_mainland_release.py --output "$release_file" && tar -tzf "$release_file"
```

发布包只包含白名单中的源码、部署样板和说明，附带 `RELEASE-MANIFEST.json` 文件哈希清单，不含任何账号、API 密钥、图片、数据库、Git 或 Node 依赖。

首先确认 `/opt/aiht-creation-studio` 和 `/var/lib/aiht-creation-studio` 都不存在，且未安装同名服务。如果已经有目录或同名服务，请停止此处的全新安装，改看第 7 步。下面命令再次检查目录和发布包，防止误覆盖旧版本。

```bash
if sudo test -e /opt/aiht-creation-studio || sudo test -e /var/lib/aiht-creation-studio; then
  echo '检测到旧源码或数据目录，停止安装；请阅读升级步骤。'
elif ! tar -tzf "$release_file" >/dev/null; then
  echo '发布包不可用，停止安装。'
else
  sudo install -d -m 0755 /opt/aiht-creation-studio && \
  sudo tar -xzf "$release_file" -C /opt/aiht-creation-studio
fi
```

如果上一步 `command -v python3` 返回的绝对路径不是 `/usr/bin/python3`，后面的临时启动命令和正式服务文件都要替换为实际 Python 3.11+ 路径。

## 3. 在私有通道创建管理员（新站必做）

程序有空库保护：没有管理员时拒绝启动正式公开站点。新站先只监听服务器的回环地址，通过 SSH 转发在你自己的电脑上创建管理员，不要关闭安全检查。

确认正式服务尚未启动，8321 端口未被占用。在服务器终端运行临时服务。它与正式服务使用同一个动态身份、同一个私有数据目录，systemd 管理该目录权限，不需要手工改为 777。

```bash
sudo systemd-run --unit=aiht-first-run \
  --property=User=aiht --property=DynamicUser=true \
  --property=StateDirectory=aiht-creation-studio --property=StateDirectoryMode=0700 \
  --property=WorkingDirectory=/opt/aiht-creation-studio \
  --property=UMask=0077 --property=NoNewPrivileges=true \
  --property=ProtectSystem=strict --property=PrivateTmp=true \
  --property=KillSignal=SIGINT --property=TimeoutStopSec=240 \
  /usr/bin/python3 -u /opt/aiht-creation-studio/server.py \
  --host 127.0.0.1 --port 8321 --data-dir /var/lib/aiht-creation-studio

sudo systemctl status aiht-first-run --no-pager
```

注意这次启动**不填写 `--public-url`**，不向公网开放 8321，不通过公开 Nginx 站点转发它。

在自己的电脑上另开 PowerShell 或终端，执行 SSH 转发（将 `your_user`、`your_server_ip` 换成真实 SSH 用户和服务器地址），不要关闭此窗口：

```bash
ssh -N -L 127.0.0.1:18321:127.0.0.1:8321 your_user@your_server_ip
```

浏览器打开 `http://127.0.0.1:18321/`。按页面提示创建管理员，填写自己的姓名、手机号和强密码。账号、密码不要进入命令、日志或仓库。若 18321 在电脑上被占用，可同步更换 SSH 命令和浏览器中的本地端口。

新建管理员成功后，回到服务器终端检查：

```bash
curl -fsS http://127.0.0.1:8321/api/bootstrap
```

确认 `setup_required` 为 `false`，再停止临时服务：

```bash
sudo systemctl stop aiht-first-run
```

关闭电脑上的 SSH 转发窗口。管理员已保存在正式服务使用的同一个数据目录。不可同时运行临时和正式两个服务。

## 4. 配置正式域名、备案号和 HTTPS

以下 `domain.example` 是占位示例，不能作为真实网站部署。使用自己的正式域名、备案号和 HTTPS 证书。备案等上线条件未就绪时只留在私有测试环节，暂不开放公网。

### 4.1 安装 Python 正式服务

```bash
sudo install -m 0644 /opt/aiht-creation-studio/deploy/mainland/aiht-creation-studio.service /etc/systemd/system/aiht-creation-studio.service
sudoedit /etc/systemd/system/aiht-creation-studio.service
```

编辑 `ExecStart=`：

- 必须将 `REPLACE_WITH_YOUR_HTTPS_URL` 换成自己的 HTTPS 根地址（如 `https://你的真实域名`，不带路径）。未替换时服务会拒绝启动。
- `--icp-number ""` 可选，空字符串表示不显示备案号；需要显示时，在引号内填写自己已经获得的真实备案号，不能借用别人的备案号。
- Python 绝对路径、内网端口、数据目录须与第 3 步一致。

检查 `ExecStart` 配置正确后执行：

```bash
grep '^ExecStart=' /etc/systemd/system/aiht-creation-studio.service
sudo systemd-analyze verify /etc/systemd/system/aiht-creation-studio.service
sudo systemctl daemon-reload
sudo systemctl enable --now aiht-creation-studio
sudo systemctl status aiht-creation-studio --no-pager
```

失败时使用 `sudo journalctl -u aiht-creation-studio -n 60 --no-pager` 查看错误；先确认管理员已创建、数据和 Python 路径正确。正式服务保持 Secure Cookie 和同源校验，不使用明文 HTTP 浏览器登录代替 HTTPS 验收。

### 4.2 配置 Nginx 公开访问

先通过云平台或自己的证书管理方式准备有效证书及真实路径。`deploy/mainland/nginx.conf.example` 是正式 HTTPS 反向代理样板，启用前：

- 将所有 `domain.example` 替换为自己的域名，与 `--public-url` 一致。
- 将 `ssl_certificate`、`ssl_certificate_key` 改为实际完整证书链和私钥路径；按实际证书续期方式修改或取消示例 ACME 验证目录。
- 用现有 Nginx 新建独立站点配置；例如使用 `/etc/nginx/conf.d/` 的环境可将已经编辑的样板放入 `/etc/nginx/conf.d/aiht.conf`。宝塔用户通过面板配置同域名 HTTPS 站点与反向代理，避免重复 `server` 配置或覆盖其它站点。

不能把源码目录或 `/var/lib/aiht-creation-studio` 配置成公开网页根目录；私有图片须通过应用鉴权访问。检查配置：

```bash
sudo nginx -t
```

检查通过才按现有 Nginx 管理方式重载（例如 `sudo systemctl reload nginx`）。按接入商要求完成域名解析和公网审批；正式安全组只开放 80/443 等 Web 必要端口以及受限管理用 SSH，绝不开放 8321。

**可选内部验收：**`nginx-local-check.conf.example` 只监听 `127.0.0.1:8088`，用于验证正式配置转发。仍须将 `domain.example` 换成已配置的实际正式域名，确认端口未被占用，配置检查通过才启用。不可向公网开放 8088。

## 5. 配置绘图 API 与授权码

从浏览器访问自己的真实 HTTPS 域名，使用第 3 步创建的管理员登录。

1. 管理员后台选择 Seedream 或 OpenAI-HK 绘图服务，按服务商实际配置填写 API 地址、模型和密钥。只在后台输入密钥，不能发给学生或上传 GitHub。
2. 管理员可以无限使用平台算力，学生凭管理员发放的授权码注册获得 10 点，成功生成一张扣 1 点。先不要批量发码。
3. 使用管理员和一个测试学生账号完成流程验收再发放正式授权码。真实生图会按服务商规则计费，确认配置和预算再测试。

## 6. 验收与运维

正式服务启动后，服务器本机可查询：

```bash
curl -fsS http://127.0.0.1:8321/api/bootstrap
```

最终从真实电脑和手机浏览器验证：域名和 HTTPS 证书正确；管理员可以登录、配置 API、生成授权码，显示无限算力；学生需有效授权码注册，不能查看管理员设置和他人的作品；个人作品保存、下载及账本符合实际生成结果，再发给班级使用。

常用运维命令：

```bash
sudo systemctl status aiht-creation-studio --no-pager
sudo journalctl -u aiht-creation-studio -n 60 --no-pager
sudo systemctl stop aiht-creation-studio
sudo systemctl start aiht-creation-studio
```

最后两条会停止／恢复服务。先结束在途生成和业务写入再停机。unit 使用 SIGINT 优雅停止，最多等待 240 秒，不因重启自动重试付费绘图；不能因浏览器暂时没看到图片就直接重复提交收费请求。

如需 60 人模拟验收，在服务器源码目录运行：

```bash
python3 scripts/mainland_load_test.py --clients 60 --image-mib 2 --output /tmp/aiht-load-report.json
```

此工具创建独立临时库和假图片，不访问生产库或外部绘图服务。报告区分首次响应错误、繁忙重试和最终业务结果，不能据此承诺公网速度、真实生图时延或固定并发人数。

正式 unit 的内存软阈值 600MiB、硬上限 900MiB 仅为小主机资源保护样板，按实际内存、带宽和图片大小评估。若内存超限造成进程终止，先核对在途任务及预留账本再恢复。

## 7. 已部署的 Python 版升级（不要重新初始化）

旧用户继续使用原有数据目录和原账号。升级只更新代码与必要的服务参数，不重置数据库、不重新注册管理员或重新赠送算力。

1. 从 GitHub `main` 下载新源码，构建新发布包并先解压到未使用的暂存目录，不覆盖运行中的 `/opt/aiht-creation-studio`。
2. 选择维护窗口，停止接收新用户操作，确认在途生成任务已结算，再执行 `sudo systemctl stop aiht-creation-studio`。
3. 备份完整数据目录、当前源码、systemd 文件与 Nginx 站点配置。SQLite 必须在服务停止后连同该目录其它数据一起备份。非公网位置的示例：

   ```bash
   backup_dir=$(mktemp -d /var/tmp/aiht-backup-XXXXXXXX)
   sudo tar -C /var/lib/aiht-creation-studio -czf "$backup_dir/data.tar.gz" .
   sudo tar -C /opt/aiht-creation-studio -czf "$backup_dir/source.tar.gz" .
   sudo cp /etc/systemd/system/aiht-creation-studio.service "$backup_dir/"
   sudo chmod 0600 "$backup_dir/data.tar.gz" "$backup_dir/source.tar.gz"
   sudo sha256sum "$backup_dir/data.tar.gz" "$backup_dir/source.tar.gz"
   ```

   另行妥善备份真实 Nginx 配置。备份含用户数据和密钥，不上传 GitHub，不放公开网页目录。
4. 将当前源码目录移动到明确、未被使用的保留位置，再将已解压的新源码目录移到原 `/opt/aiht-creation-studio` 位置。保留旧版本供回退；确认私有数据目录未被移动或覆盖。
5. 已有站点继续使用原真实 `--public-url`、证书路径、站点配置和数据目录，不使用通用样板覆盖。原来写死的备案号现在改成可配置：在正式服务 `ExecStart` 中追加 `--icp-number "你自己的真实备案号"`，新代码才会继续显示它。编辑 unit 后执行 `sudo systemctl daemon-reload`，再启动正式服务。
6. 重新进行第 6 步验收，核对原账户、作品和历史算力记录都存在。如果发生异常，暂停新写入，用对应版本与备份有计划地回退；不能盲目以旧数据库覆盖新写入的数据。

迁移旧 Cloudflare 数据是独立的高级操作，参见[旧数据迁移说明](../../docs/migration/旧Cloudflare数据迁移.md)。已经运行 Python 版或全新部署的用户无需运行迁移脚本。

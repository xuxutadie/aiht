# 一次性注册授权码

2026-11-22 用户已确认：新用户必须凭8位数字授权码注册，一人一码、注册成功后失效；管理员可持续生成，原账户不补码，首次注册仍赠10点。同步更新第一课讲稿。此确认包含新增数据表与注册后台改造。

## 实现约定

- 共享注册字段为 `authorization_code`；登录与首次管理员初始化不要求授权码。
- Python SQLite 与 Cloudflare D1 均新增 `authorization_codes`，不重建或清空已有业务表。
- 安全随机生成10000000至99999999；仅保存SHA-256摘要、末4位、生成者与生成时间、使用者与使用时间。完整码只在管理员生成时返回，并提示及时复制保存；不写日志或浏览器持久存储。
- 管理员单批生成1至100个，不设置累计生成数量上限。GET/POST `/api/admin/authorization-codes` 均在服务端验证管理员权限。历史按ID倒序游标分页，默认50条。
- 注册中的有效码校验、账户创建、10点赠送与用码记录必须原子完成。SQLite使用已有写事务；D1使用单次原子batch内条件写入。重复手机号、无效资料、重复用码不得遗留账户或消耗授权码。
- 复用原注册限流；不新增依赖、语言模型调用、外部服务或.env字段。不改变既有会话/密码/余额/草稿/作品。

## 验收与交付

先覆盖空码、错误格式、无效码、重复使用、并发同码、失败回滚、管理员权限、分页及原账户登录，再检查浏览器注册与后台复制流程。所有验收使用隔离数据与模拟绘图，不调用收费模型。

D1迁往SQLite时，同时保留新授权码表，兼容尚无该表的旧快照；发布包包含新前端模块。完成本地验证后另行核对当前云端部署状态，不能把本地通过写成线上已发布，也不恢复备案期间暂停的域名。
